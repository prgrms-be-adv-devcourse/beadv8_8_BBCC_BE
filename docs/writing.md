# 문서 고치는 법

- 레포의 `docs/`를 PR로 고친다. develop에 머지되면 문서 사이트와 GitHub 위키가 자동으로 바뀐다. 위키에서 고친 내용은 다음 동기화 때 덮어쓰인다
- API · 이벤트를 바꾸는 PR에서 해당 문서도 같이 고친다(이벤트는 [토픽 목록](kafka/topics.md)의 받는 곳 칸까지). 기획서 PR은 팀원 전체가 리뷰한다
- 문서만 고칠 때는 `docs:` 커밋으로 올린다. 그림은 문서 옆 `images/`에 둔다
- 파일 이름에 날짜 · 판 번호를 붙이지 않는다. 이전 내용은 `git log -p <파일>`로 본다

## 글을 더하거나 옮길 때

- 새 글은 분야 폴더(`planning/` · `kafka/` · `api/`)에 둔다. 첫 줄은 `# 제목`이다
- 그 폴더의 `README.md` 목차에 `- [제목](파일.md) · 한 줄 설명`을 더한다. 사이트 메뉴와 위키 사이드바가 이 목차 순서를 따른다
- 새 분야 폴더를 만들면 `docs/README.md`의 "분야"에도 한 줄 더한다
- 링크는 파일 경로(`../api/README.md`)로 건다. 사이트와 위키 주소로는 빌드할 때 바뀐다. 없는 파일을 가리키면 빌드가 실패한다

## 사이트를 로컬에서 보기
