# 자동 운영 점검

Grafana → Kidly → **Kidly 자동 운영 점검**. 서비스 오류 화면 위쪽 링크에서도 엽니다.
최신 점검 행을 펼치면 원인 후보·확인 순서·대응 제안이 나옵니다. 최신 메모는 30초마다 조회합니다.
형식화 상세는 페이지 로드 시점의 스냅샷이며, 새 결과는 위의 최신 점검 행에서 확인합니다.

**외부 AI/API·키·새 이미지·새 플러그인 없이 기존 서버에서 실행합니다.**
기존 서버 자원은 사용하지만 별도 API 요금은 없습니다. 앱 코드·MCP 권한·운영시간은 바꾸지 않습니다.

## 읽는 법

- 운영 대상 DOWN/누락, 메모리·CPU·디스크, 느린 평균 응답과 DB 대기, 5xx, Kafka lag를 조합합니다
- 의도적 중지·전환은 장애로 취급하지 않습니다. 미수집·저트래픽은 판단 보류입니다
- 원인은 후보입니다. 앱/서버를 자동으로 중지·재시작하거나 데이터·설정을 바꾸지 않습니다
- 점검 시각과 상단 경과 시간을 보세요. 1시간이 넘으면 오래된 결과입니다
- 실패 시 이전 결과를 접고 경고합니다. 수집이 끊기면 미수집으로 표시합니다

## 실행·중지

관리자는 설치할 unit 두 개의 내용을 승인된 PR과 대조합니다. 서버 관리자가 머지·배포 후 `sudo bash /opt/app/monitoring/ai-summary/install-timer.sh`를 한 번 실행합니다.
**작업 종료 후 30분마다** 실행하며 서버가 꺼져 있으면 실행하지 않습니다.
배포 계정의 sudo 권한을 넓히지 않습니다. 일반 배포는 설치 여부만 안내하고 점검 코드를 갱신합니다.

- 실행: `sudo systemctl start kidly-ai-summary.service` (최근 실행 후 30분 이내면 중복 점검 생략)
- 상태: `systemctl status kidly-ai-summary.timer kidly-ai-summary.service`
- 중지: `sudo systemctl disable --now kidly-ai-summary.timer` 후 실행 중인 service도 stop
- 이전 develop으로 시험 원복할 때는 timer/service부터 중지하고 이번에 설치한 unit 두 개를 제거한 뒤 `daemon-reload`합니다

상태는 `ai-summary-state/state.json`(0600)에 마지막 성공 1개만 유지합니다. dashboard 하위 경로만 Grafana에 읽기 전용으로 마운트합니다.
기존 Alloy가 `operations/ai-summary.prom`의 시각/성공 여부를 수집합니다. 요약 문장은 지표 라벨에 넣지 않습니다. 점검 메모만 localhost Loki의 고정 stream에 기록합니다. 앱 로그를 읽지 않습니다.
Loki의 기존 14일 보관 정책을 따르며 공개 포트·새 저장소를 추가하지 않습니다. Loki 장애 시 이전 메모가 남을 수 있으니 실패/경과 카드도 확인합니다.
기존 파일명·UID의 `ai-summary`는 호환용 이름이며 AI 호출 기능은 없습니다.

## 기준·제약

- 최근 30분 OOM 종료가 있으면 현재 메모리 여유와 별개로 종료 대상 확인을 안내합니다
- 환경 전환이 10분 넘게 남아 있으면 실패한 작업 여부를 경고합니다
- 현재 메모리 여유 <10%, CPU >90%, 디스크 >80%. 지속 경보가 아니라 점검 시점의 확인 후보입니다
- HTTP: 최근 30분 요청 ≥20건, 평균 응답 >1초. p95가 아닙니다
- 5xx 시계열이 없어도 요청·응답시간 지표가 있으면 오류 누락 경고를 만들지 않습니다. 요청 지표까지 없으면 판단 보류입니다
- 오류: 요청 ≥20건·오류 ≥5건·5xx >5%. Gateway와 서비스 요청을 합산하지 않습니다
- DB: 현재 연결 대기 >0 또는 풀 사용률 ≥90%. 느린 평균 응답과 대기가 동반되면 DB 확인 순서를 먼저 안내합니다
- Kafka: 현재 환경 합계 lag >1,000이면 그룹별 추이를 확인하도록 안내합니다. 합계 한 번으로 증가 추세를 단정하지 않습니다
- 자원 값은 수집된 서버 중 최악 값입니다. 수집이 끊긴 서버는 집계에서 빠질 수 있습니다. 앱의 원인 서버를 단정하지 않습니다. DB 상세/로그는 사람이 관련 화면에서 확인합니다
- 기준은 초기 후보이며 실제 트래픽에 맞춰 PR로 보정합니다. 기존 경보/Slack 설정은 바꾸지 않습니다
- HTTP 각 호출 20초, 작업 300초, 메모리 96MiB·CPU 25% 제한. 중복 실행 잠금, 자동 재시도 없음

검증: `python3 -m unittest discover -s deploy/monitoring/tests -p 'test_*.py'`
로컬 미리보기: `summary.py --state-dir /tmp/kidly-preview/state --fixture <합성 지표 JSON>`

OOM 증가는 첫 수집 이전 사건을 잡지 못할 수 있습니다. 0이나 누락만으로 과거 OOM이 없었다고 판단하지 않습니다.
